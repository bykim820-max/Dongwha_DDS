## ⏱ 시작 전 30초 요약 — 이 5가지만 기억하세요

1. **색상·크기는 이름으로 부른다.** `#14BC62`, `13px` 대신 → `Color/bg/interactive/primary`, `spacing/12`
2. **이모지를 아이콘 자리에 쓰지 않는다.** 🛒 👤 ✅ 대신 → 표준 라인 아이콘 이름(`cart`, `user`, `check`)
3. **내용이 다르면 Tabs, 보기 방식만 다르면 Segmented.** 헷갈리면 §1.1 표 확인
4. **오류 문구에는 반드시 "다음에 할 일"을 넣는다.** "오류가 발생했습니다" 단독 금지
5. **버튼은 동사로.** `확인`·`예` 대신 → `저장`·`삭제`·`거래처 등록`

> 이 5가지는 개발 단계에서 **자동 검사로 걸러지거나 리뷰에서 반려**됩니다(§4).
> 기획·디자인 단계에서 미리 지키면 수정 왕복이 사라집니다.

# SECTION 1. 내비게이션 컴포넌트 활용 가이드

내비게이션은 사용자에게 **"지금 어디에 있고, 어디로 갈 수 있는지"** 를 알려주는 장치입니다.
같은 목적에 서로 다른 컴포넌트를 쓰면 사용자는 화면마다 새로 배워야 합니다. 아래 기준 하나로 통일합니다.

## 1.1 한눈에 고르기

기획 중인 화면에서 아래 질문에 답해 보세요.

```
Q1. 클릭하면 "서로 다른 내용"의 패널이 바뀌나요?          → Tabs
Q2. 내용은 같고 "보는 방식·범위"만 바뀌나요?              → Segmented Control
Q3. 지금 페이지가 "몇 단계 깊이"에 있는지 보여주고 싶나요?  → Breadcrumb
Q4. 목록 데이터가 많아 "여러 페이지로 나눠" 보여주나요?     → Pagination
Q5. 앱의 "전체 메뉴 이동"인가요?                          → SNB (사이드 메뉴, layout.md)
```

| 상황 | 컴포넌트 | 항목 개수 제한 | 예시 |
|------|----------|--------------|------|
| 서로 다른 콘텐츠 패널 교체 | **Tabs** | 2~7개 (8개 이상 금지) | 프로필 / 알림 / 보안 |
| 같은 콘텐츠의 표시 방식·범위 전환 | **Segmented Control** | 2~4개 (5개 이상은 Select) | 일별 / 주별 / 월별 |
| 현재 페이지의 계층 경로 표시 | **Breadcrumb** | 3단계 이하 권장 (최대 4) | 홈 / 주문 / 주문번호 #12345 |
| 대량 목록의 페이지 나누기 | **Pagination** | — | 1 2 3 … 25 |

> **가장 자주 틀리는 것: Tabs vs Segmented.**
> - **Tabs** = 서랍장. 서랍마다 **다른 물건**이 들어 있다. (프로필 서랍, 알림 서랍)
> - **Segmented** = 안경. 같은 물건을 **다르게 보는** 도구다. (일별로 보기, 월별로 보기 / 카드로 보기, 목록으로 보기)

> ⚠️ **디자이너 참고** — Tabs·Segmented·Breadcrumb는 현재 **사양(문서)이 먼저 확정**된 상태로,
> Figma 라이브러리 게시는 대기 중입니다([navigation.md §0](../components/navigation.md)).
> 라이브러리에서 검색해도 나오지 않으니, 게시 전까지는 **이 가이드의 사양대로 그리고**
> "DDS Tabs 사양 준수"라고 시안에 명시하세요. 게시되면 컴포넌트 인스턴스로 교체합니다.

## 1.2 Tabs — 정보를 병렬로 나눠 담을 때

### 언제 쓰나요

- 한 화면 안에서 **성격이 다른 정보 묶음**을 나란히 배치할 때 (예: 설정 화면의 프로필·알림·보안·결제)
- 목록을 **상태별로 나눠 볼** 때 (예: 전체 / 진행 중 / 완료)

### 언제 쓰면 안 되나요

| 이런 상황이면 | 대신 이걸 쓰세요 |
|--------------|----------------|
| 탭이 **8개 이상** 필요하다 | SNB(사이드 메뉴) 또는 Select(드롭다운) — 정보 구조 재검토 |
| 탭 안에 또 탭이 필요하다 (2단 탭) | 금지. 정보 구조를 다시 설계 |
| 내용은 같고 보기 방식만 바뀐다 | Segmented Control |
| 다른 페이지로 이동한다 | SNB 또는 링크 — Tabs는 같은 페이지 안의 전환 |

### 기획 시 지정할 옵션

| 옵션 | 선택지 | 기본값 | 기획서에 쓸 때 |
|------|--------|--------|---------------|
| 모양 (`variant`) | 언더라인 / 알약(pill) | **언더라인** | 특별한 이유 없으면 기본값 |
| 높이 (`size`) | md(44px) / sm(36px) | **md** | sm은 데이터 밀집 화면 + 데스크톱 전용. **모바일은 항상 md** |
| 정렬 (`align`) | 좌측 정렬 / 균등 분할 | **좌측 정렬** | 균등 분할은 모바일에서 탭 3개 이하일 때만 |
| 넘칠 때 (`overflow`) | 가로 스크롤 / "더 보기" 메뉴 | **가로 스크롤** | 데스크톱 고정 폭 화면은 메뉴 접기 |

### 상태별 주의사항 (기획·디자인 체크)

| 상태 | 화면에서 이렇게 보입니다 | 기획·디자인 시 주의 |
|------|------------------------|-------------------|
| **Default** (기본) | 회색 계열 글자(`Color/text/tertiary`), 밑줄 없음 | 기본 탭도 읽을 수 있는 대비여야 함 — 토큰 그대로 쓰면 보장됨 |
| **Hover** (마우스 올림) | 글자가 한 단계 진해짐 | 별도 디자인 불필요 — 시스템 규칙 |
| **Active/Selected** (선택됨) | 진한 글자 + **굵은 글씨** + 초록 밑줄 2px | **색 하나만으로 선택 표시 금지.** 색+굵기+밑줄 3중 표시가 규칙 |
| **Disabled** (비활성) | 흐린 글자(`Color/text/disabled`) | "왜 비활성인지" 툴팁이나 안내 문구를 함께 기획할 것 |

> **선택 밑줄이 왜 초록색인가요?** 파란색으로 하면 키보드 포커스 표시(파랑)와 구분되지 않기 때문입니다.
> 선택 = 브랜드 초록, 포커스 = 파랑으로 역할이 나뉘어 있습니다. 임의로 바꾸지 마세요.

### 라벨 작성 규칙

- **명사구, 1~2어절, 마침표 없음**: `프로필` · `알림` · `보안` ✅
- ❌ 동사형(`설정하기`) — 동사는 버튼의 것
- ❌ 군더더기(`알림 관리`, `보안 페이지`) — `알림`, `보안`이면 충분
- 개수 배지는 숫자만: `알림 12` (999 초과 시 `999+`)
- 영어로 바뀌면 폭이 최대 +80% 늘어납니다. **라벨을 짧게** 유지하세요

### 추가로 기획서에 명시하면 좋은 것

- **탭 상태는 주소(URL)에 남습니다** — 새로고침·뒤로가기 후에도 보던 탭 유지. 별도 요구가 없어도 이것이 기본 동작입니다
- 탭 전환 시 **데이터를 새로 불러오는** 무거운 화면이면 기획서에 "수동 활성화(Enter로 확정)"라고 명시하세요

## 1.3 Segmented Control — 하나만 고르는 전환 토글

### 언제 쓰나요

**같은 데이터를 다르게 보는 단일 선택(Single-choice)** 전용입니다. 항상 하나가 선택되어 있고, 다른 것을 누르면 즉시 바뀝니다.

- 집계 구간 전환: `일별 / 주별 / 월별`
- 보기 방식 전환: `카드 / 목록`
- 언어 전환: `한국어 / English`

### 언제 쓰면 안 되나요

| 이런 상황이면 | 대신 이걸 쓰세요 |
|--------------|----------------|
| 선택지가 **5개 이상** | Select(드롭다운) |
| **여러 개**를 동시에 켤 수 있어야 한다 | Checkbox 또는 필터 칩 |
| 켜기/끄기 **하나뿐**이다 | Switch |
| 누르면 다른 내용의 패널이 바뀐다 | Tabs |

### 상태별 주의사항

| 상태 | 화면에서 이렇게 보입니다 | 기획·디자인 시 주의 |
|------|------------------------|-------------------|
| **Default** (비선택) | 연한 회색 트랙 위 투명 버튼, 회색 글자 | — |
| **Hover** | 미세한 배경 변화 | 별도 디자인 불필요 |
| **Active/Selected** | **흰 면 + 그림자**가 올라오고 글자 굵어짐 | 선택 표시에 브랜드색을 쓰지 않는 것이 규칙 — 화면에 여러 개 놓아도 시끄럽지 않게 하기 위함 |
| **Disabled** | 흐린 글자 | 항목 하나만 비활성도 가능. 이유를 툴팁으로 |

### 라벨 작성 규칙

- Tabs보다 더 짧게 — **1어절**: `일별` · `주별` · `월별`
- 그룹 전체에 "무엇을 고르는지" 이름이 필요합니다(스크린리더용). 기획서에 함께 적어 주세요 — 예: *"집계 구간"*

## 1.4 Breadcrumb — 현재 위치(Depth) 보여주기

### 언제 쓰나요

계층이 **3단계 이상 깊은 구조**에서, 사용자가 "지금 어디에 있는지"와 "상위로 가는 길"을 보여줄 때.

```
홈 / 주문 / 주문번호 #12345
```

### 언제 쓰면 안 되나요

- **2단계 이하**의 얕은 구조 → 뒤로가기 버튼 하나로 충분합니다
- **모바일 화면** → Breadcrumb를 줄여서 넣지 말고 **숨기고 뒤로가기 버튼으로 대체**합니다 (중간을 접어 2~3개만 남기면 위치를 오해하게 만듭니다)

### 꼭 지켜야 하는 규칙 (기획서에 그대로 반영)

| 규칙 | 내용 |
|------|------|
| 깊이 | **3단계 이하 권장, 최대 4단계** |
| 마지막 항목 | **현재 페이지 = 링크가 아님.** 진한 글자로만 표시 (자기 자신으로 가는 링크는 혼란만 줌) |
| 구분자 | 슬래시 `/` 고정. 화살표(>)나 아이콘으로 바꾸지 않음 |
| 4단계 초과 시 | **중간을 `…` 메뉴로 접기** — 첫 항목과 마지막 2개는 항상 노출: `홈 / … / 주문 / 주문번호 #12345` |
| 긴 라벨 | 말줄임(`…`) 처리 + 마우스 올리면 전체 문구 표시 |
| 항목 이름 | **해당 페이지 제목과 같은 단어** 사용 — 페이지 제목이 "주문 목록"이면 Breadcrumb도 `주문`(축약형은 사전 합의된 것만) |

### 상태별 주의사항

| 상태 | 표시 |
|------|------|
| Default (중간 항목) | 회색 글자, 클릭 가능 |
| Hover | 글자 진해짐 + 밑줄 |
| Active (현재 페이지 = 마지막 항목) | 진한 글자 + 굵기. **클릭 불가** |
| Disabled | 사용하지 않음 — 갈 수 없는 경로는 아예 표시하지 않습니다 |

## 1.5 Pagination — 대량 데이터 나눠 보여주기

### 언제 쓰나요

테이블·목록의 데이터가 많아 **한 화면에 다 보여줄 수 없을 때**. 패턴은 4가지 중에서 고릅니다.

| 패턴 | 이럴 때 선택 | 예 |
|------|-------------|-----|
| **번호형** (1, 2, 3, …) | 전체 페이지 수가 의미 있을 때 — 업무 테이블 기본 | 관리자 주문 목록 |
| **이전/다음** | 단순 순차 탐색만 필요할 때 | 문서 상세 넘기기 |
| **무한 스크롤** | 모바일, 피드형 콘텐츠 | 알림 피드 |
| **더 보기 버튼** | 페이지 개념이 약한 데이터 | 검색 결과 추가 로드 |

> **업무 시스템 테이블은 번호형이 기본**입니다. 무한 스크롤은 "몇 번째까지 봤는지"를 잃게 만들어 업무용 데이터 화면에 부적합합니다.

### 기획서에 함께 명시할 것

- **현재 위치 표시**: `11–20 / 총 248건` 형식 (어디까지 봤는지 항상 보여줌)
- **페이지당 행 수 선택지**: `10 / 25 / 50 / 100` 중 제공, 화면 성격에 맞는 기본값 지정 (일반적으로 25)
- 페이지 이동 시 **목록 상단으로 스크롤** 여부

### 상태별 주의사항

| 상태 | 주의 |
|------|------|
| Default | 번호는 클릭 가능한 회색 글자 |
| Hover | 배경 표시 |
| Active (현재 페이지) | 진한 표시 + 클릭 불가. **색만으로 구분 금지** — 굵기·배경 동반 |
| Disabled | **1페이지에서 "이전" 버튼, 마지막 페이지에서 "다음" 버튼**은 비활성으로 표시 (숨기지 않음) |

## 1.6 복사용 — 화면 정의서 표기 템플릿

기획서·화면 정의서에 아래 블록을 복사해 채워 넣으세요. 개발자가 추가 질문 없이 구현할 수 있는 최소 정보입니다.

```
■ 내비게이션 정의

컴포넌트: Tabs (언더라인 / md / 좌측 정렬)
탭 구성:  [프로필] [알림(배지: 미읽음 수)] [보안] [결제]
기본 선택: 프로필
상태 유지: URL 반영 (새로고침·뒤로가기 시 유지)
모바일:   4개 이상이므로 가로 스크롤
비활성 탭: 없음
```

```
■ 보기 전환 정의

컴포넌트: Segmented Control (md)
그룹 이름: 집계 구간          ← 스크린리더용, 필수
선택지:   [일별] [주별] [월별]
기본 선택: 일별
모바일:   가로 100% 균등 분할
```

```
■ 경로 표시 정의

컴포넌트: Breadcrumb
경로:     홈 / 주문 / 주문번호 #{번호}
마지막 항목: 링크 없음 (현재 페이지)
모바일:   숨김 → 뒤로가기 버튼으로 대체
```

```
■ 페이지네이션 정의

# SECTION 2. 스타일 및 아이콘 사용 규칙 — 하드코딩 금지

## 2.1 디자인 토큰이 뭔가요?

**색상과 크기에 붙인 "공식 이름표"** 입니다.

시안이나 기획서에 `#14BC62`(색상 코드)나 `13px`(임의 수치)를 직접 적는 것을 **하드코딩**이라고 합니다.
대신 DDS는 모든 색·간격·모서리에 이름을 붙여 두었습니다.

| 직접 값 (하드코딩) | 토큰 (이름표) | 이름의 뜻 |
|------------------|--------------|----------|
| `#14BC62` | `Color/bg/interactive/primary` | "주요 액션 버튼의 배경색" |
| `#DC2626` 비슷한 빨강 | `Color/text/danger` | "위험·오류를 알리는 글자색" |
| `13px`, `15px` | `spacing/12`, `spacing/16` | "간격 12, 간격 16" (8pt 그리드) |

**왜 이름으로 불러야 하나요?**

1. **다크 모드가 공짜로 됩니다.** `Color/bg/primary`는 라이트에서 흰색, 다크에서 어두운 색으로 자동 전환됩니다. `#FFFFFF`로 박아 넣으면 다크 모드에서 깨집니다.
2. **브랜드 색이 바뀌어도 한 곳만 고칩니다.** 이름을 쓴 화면은 자동 반영, 코드값을 쓴 화면은 하나하나 찾아 고쳐야 합니다.
3. **접근성이 검증된 값입니다.** 토큰 색상은 글자 대비(WCAG AA)가 이미 검증되어 있습니다. 임의 색은 "예쁘지만 안 읽히는" 화면을 만듭니다.
4. **개발 단계에서 자동 검사로 걸러집니다.** 시안에 하드코딩 값이 있으면 개발자가 어차피 토큰으로 바꿔야 하고, 그 과정에서 의도와 다른 색이 될 수 있습니다.

> **비유하자면** — 계좌번호(`110-123-456789`)를 외우는 대신 예금주 이름("동화 급여계좌")으로 저장하는 것과 같습니다.
> 번호가 바뀌어도 이름은 그대로니까요.

## 2.2 자주 쓰는 토큰 치트시트

시안 주석·기획서에 이 이름을 그대로 적으면 됩니다. 전체 목록: [colors.md](../foundations/colors.md) · [spacing.md](../foundations/spacing.md)

**색상 — 배경**

| 쓰임새 | 토큰 이름 |
|--------|----------|
| 화면·카드의 기본 흰 배경 | `Color/bg/primary` |
| 한 단계 가라앉은 배경 (섹션 구분) | `Color/bg/secondary` |
| 더 가라앉은 배경 (Segmented 트랙 등) | `Color/bg/tertiary` |
| 주요 액션 버튼 (브랜드 초록) | `Color/bg/interactive/primary` |
| 성공 / 경고 / 오류 / 정보 배경 | `Color/bg/success` · `warning` · `danger` · `info` |
| 비활성 배경 | `Color/bg/disabled` |

**색상 — 글자**

| 쓰임새 | 토큰 이름 |
|--------|----------|
| 제목·본문 기본 | `Color/text/primary` |
| 보조 설명 | `Color/text/secondary` |
| 힌트·자리표시 수준 | `Color/text/tertiary` |
| 오류 문구 | `Color/text/danger` |
| 비활성 글자 | `Color/text/disabled` |

**간격 (8의 배수 그리드)**

| 쓰임새 | 토큰 이름 |
|--------|----------|
| 버튼 안쪽 좌우 여백 | `spacing/12` ~ `spacing/16` |
| 카드 안쪽 여백 | `spacing/16` ~ `spacing/24` |
| 섹션 사이 간격 | `spacing/32` ~ `spacing/48` |
| 페이지 좌우 여백 (모바일) | `spacing/16` ~ `spacing/24` |

> **13px, 15px, 18px 같은 값은 존재하지 않습니다.** 시안에서 이런 수치가 나오면 가장 가까운 토큰(12·16·24…)으로 스냅하세요.

### Do & Don't

| ❌ Don't (하드코딩) | ✅ Do (토큰) |
|--------------------|-------------|
| 버튼 색상: `#14BC62` | 버튼 색상: `Color/bg/interactive/primary` |
| 오류 문구는 빨간색(`#FF0000`) | 오류 문구: `Color/text/danger` |
| 카드 여백 `15px` | 카드 여백 `spacing/16` |
| "회색 배경 아무거나" | `Color/bg/secondary` (지정) |
| 시안마다 다른 초록 3종 | 브랜드 초록은 `interactive/primary` 하나 — **주요 액션 전용** |

## 2.3 이모지 하드코딩 금지 — 표준 아이콘만

> **이모지를 아이콘 자리에 쓰는 것은 예외 없이 금지입니다.** → [icons.md §0](../components/icons.md)

| ❌ Don't | ✅ Do |
|---------|------|
| 👤 내 정보 | 라인 아이콘 `user` |
| 🔔 알림 | 라인 아이콘 `bell_on` |
| ✅ 체크 표시 | 라인 아이콘 `check-square` + 성공 색 토큰 |
| 💬 댓글·메시지 | 라인 아이콘 `message-square` |
| "···" 를 글자로 입력 | 라인 아이콘 `more-horizontal` (더보기 메뉴) |
| 버튼 라벨 "저장 💾" | 버튼 라벨 "저장" (아이콘 필요 시 라인 아이콘 지정) |

> 위 이름들은 현재 Figma 라이브러리에 **실제 게시된** 아이콘입니다. 전체 목록: [icons.md §1](../components/icons.md)
> 게시된 세트는 아직 소수입니다 — 장바구니·경고 삼각형처럼 **목록에 없는 아이콘은 §2.3-3의 요청 절차**를 따르세요.

**왜 안 되나요?**

- 이모지는 **기기·브라우저마다 다르게** 생겼습니다. 같은 🔔이 iOS·Windows·안드로이드에서 전부 다릅니다.
- 색을 통제할 수 없어 다크 모드·상태색과 어긋납니다.
- 스크린리더가 "웃는 얼굴 이모지"처럼 **엉뚱하게 읽어** 접근성을 해칩니다.

**표준 아이콘은 어떻게 쓰나요?**

1. 아이콘은 **얇은 라인(아웃라인) 스타일 한 세트**로 통일되어 있습니다 (Lucide/Feather 계열). Figma 라이브러리에서 이름으로 검색해 사용하세요.
2. 시안·기획서에는 이모지 대신 **아이콘 이름**을 적으세요 — 예: `아이콘: bell_on (알림)`
3. 필요한 아이콘이 라이브러리에 없으면 **임의 이모지·타 스타일 아이콘으로 때우지 말고**, 디자인시스템 담당자에게 같은 라인 세트로 추가 요청하세요.
4. 예외: 금액의 `₩`, 비율의 `%` 처럼 **문장 속 글자로 쓰는 기호**는 허용됩니다. 아이콘 칩·버튼·메뉴 자리에만 금지입니다.

> 참고: 문서(기획서·위키)에 쓰는 이모지는 무방합니다. 금지 대상은 **화면(UI)에 노출되는 이모지**입니다.

# SECTION 3. UX 라이팅 & 공통 메시지 가이드 (한/영)

문구는 눈에 보이는 인터페이스입니다. 규범 전체는 [writing.md](../foundations/writing.md), 리뷰용 1장 점검표는 [writing-checklist.md](../foundations/writing-checklist.md)를 쓰고, 여기서는 **기획서에 문구를 적을 때 바로 쓰는 핵심**만 담았습니다.

## 3.1 보이스 & 톤

**보이스(정체성)는 하나로 고정** — *정중하고 담백한 실무 동료*. 상황에 따라 **톤(온도)만** 조절합니다.

| 상황 | 톤 | 예시 문구 |
|------|-----|----------|
| 일반 안내 | 중립·담백 | 변경 사항은 자동으로 저장됩니다. |
| 작업 성공 | 짧게 사실만 | 저장했습니다. |
| 입력 오류 | 차분, 해결 지향 | 이메일 형식을 확인해 주세요. |
| 시스템 오류 | 침착, 책임 있는 | 일시적인 문제로 불러오지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 파괴적 액션 | 단호, 구체적 | 주문 3건을 삭제합니다. 삭제 후에는 복구할 수 없습니다. |
| 빈 화면 | 안내·유도 | 아직 등록된 거래처가 없습니다. |

**항상 금지**: 과장(“완벽하게 저장되었습니다!”) · 사과 남발(“정말 죄송합니다”) · 의성어(“앗!”) · 이모지 · 느낌표

## 3.2 표준 표기법

**어미 (한국어)**

| 유형 | 어미 | 예 |
|------|------|-----|
| 결과·완료 | `~했습니다` | 삭제했습니다. |
| 상태·사실 | `~합니다 / ~입니다` | 30일간 보관됩니다. |
| 행동 요청 | `~해 주세요` | 파일을 선택해 주세요. |
| 라벨·버튼·제목 | 명사형·동사 어간 | 저장 · 주문 내역 |

❌ `~하십시오`(고압적) · `~해요`체(가벼움) · `~하시기 바랍니다`(장황)

**문장부호**

| 부호 | 규칙 |
|------|------|
| 마침표 `.` | 완전한 서술문에만 (헬퍼·에러·토스트 본문) |
| 마침표 없음 | 제목 · 버튼 · 메뉴 · 탭 · 툴팁 · 테이블 헤더 |
| 느낌표 `!` | 사용 안 함 |
| 물음표 `?` | 확인 다이얼로그 **제목**에만 |
| 말줄임표 | `…` 한 글자 (마침표 3개 `...` 금지) |

**날짜 · 시간 · 화폐 (한/영)**

| 항목 | 한국어 | English |
|------|--------|---------|
| 날짜(문장) | 2026. 6. 19. | Jun 19, 2026 |
| 날짜(테이블·데이터) | 2026-06-19 | 2026-06-19 |
| 날짜+시간 | 2026. 6. 19. 오후 3:24 | Jun 19, 2026, 3:24 PM |
| 숫자 | 1,234,567 (천 단위 콤마) | 1,234,567 |
| 통화(원) | ₩1,234,000 (기호와 숫자 붙임) | KRW 1,234,000 |
| 수량 | 3건 · 12개 · 5MB (단위 붙여쓰기) | 3 items · 20 MB (공백) |

**에러 메시지 공식** — 두 요소 중 하나라도 빠지면 반려됩니다.

```
[무슨 일이 있었는지] + [사용자가 다음에 할 일]
```

```

❌ 입력값이 잘못되었습니다.                (사용자 탓 + 무엇이 문제인지 없음)
✅ 파일을 업로드하지 못했습니다. 20MB 이하 파일만 첨부할 수 있습니다.

## 3.3 한/영 다국어 매칭 테이블 — Do & Don't

한국어가 원문 기준(SSOT)이고 영어는 **직역하지 않습니다**. 영어는 문장 첫 글자만 대문자(Sentence case)이며, 버튼도 `Save changes`(❌ `Save Changes`)로 씁니다.

| 상황 | ✅ 한국어 | ✅ English | ❌ 이렇게 쓰지 않기 |
|------|----------|-----------|-------------------|
| 저장 성공 | 저장했습니다. | Saved. | Save Success! / 저장이 완료되었습니다! |
| 필수 미입력 | 이메일을 입력해 주세요. | Enter your email. | 이메일은 필수 입력값입니다 |
| 형식 오류 | 이메일 형식을 확인해 주세요. | Enter a valid email address. | 잘못된 이메일입니다 |
| 저장 실패 | 저장하지 못했습니다. 다시 시도해 주세요. | We couldn't save your changes. Try again. | 처리에 실패하였습니다 |
| 세션 만료 | 로그인이 만료되었습니다. 다시 로그인해 주세요. | Your session expired. Log in again. | 세션이 종료됨 |
| 네트워크 | 네트워크에 연결되어 있지 않습니다. 연결을 확인한 뒤 다시 시도해 주세요. | You're offline. Check your connection and try again. | 인터넷 오류 |
| 권한 없음 | 이 항목에 접근할 권한이 없습니다. 관리자에게 문의해 주세요. | You don't have access to this item. Contact your administrator. | Access Denied (403) |

**자주 쓰는 라벨 대응** (전체: [i18n.md §9](../foundations/i18n.md))

| 한국어 | English | 비고 |
|--------|---------|------|
| 저장 / 취소 / 닫기 | Save / Cancel / Close | 창 닫기는 Cancel이 아니라 Close |
| 삭제 | Delete | 영구 삭제 = Delete permanently |
| 수정 / 추가 | Edit / Add | 신규 생성 절차는 Create |
| 다시 시도 | Try again | Retry보다 평이한 표현 |
| 자세히 보기 / 더 보기 | View details / Show more | 상세 이동과 목록 확장을 구분 |
| 내보내기 / 가져오기 | Export / Import | |
| 로그인 / 로그아웃 | Log in / Log out | 명사형은 Login |
| 설정 | Settings | 영어는 항상 복수형 |
| 필수 / 선택 | Required / Optional | |

**다국어 관련, 기획서에서 미리 지킬 것**

- 버튼·라벨 폭을 **고정 수치로 지정하지 마세요.** `저장 → Save`는 폭이 +28%, `취소 → Cancel`은 +80% 늘어납니다. "최소폭 + 내용에 따라 신축"으로 기획합니다
- **이미지 안에 텍스트를 넣지 마세요.** 번역이 불가능합니다
- 문장을 쪼개 조립하는 기획 금지 — "`{이름}`님의 " + "주문 목록" 처럼 반쪽 문장 2개가 아니라, **완전한 문장 1개**(`{이름}님의 주문 목록`)로 정의하세요. 언어마다 어순이 다릅니다

## 3.4 복사용 — 공통 메시지 템플릿

아래 문구는 검증된 표준 문안입니다. 기획서에 그대로 복사해 쓰고, 상황이 표에 없을 때만 §3.2 공식으로 새로 작성하세요.

**Placeholder (입력창 자리표시)** — 예시 값만 넣습니다. 라벨을 대신하지 않습니다.

```
[이메일]        name@example.com
[전화번호]      010-1234-5678
[날짜]          2026-06-19
[검색]          거래처명, 사업자번호로 검색
[금액]          1,000,000
```

- ❌ Placeholder에 "이메일을 입력하세요" — 라벨과 헬퍼가 할 일입니다. 입력 시작하면 사라져서 조건을 잊게 됩니다.
- 입력 조건은 **입력창 아래 헬퍼 텍스트**로 미리 안내: `영문·숫자 조합 8자 이상`

**Toast (짧은 완료 알림 — 잠시 후 자동으로 사라짐)**

```
저장했습니다.
삭제했습니다.  [실행 취소]
주문 3건을 삭제했습니다.
변경 사항을 적용했습니다.
```

- 성공 Toast는 1문장 + 마침표. 함께 놓인 액션 버튼(`실행 취소`)에는 마침표를 찍지 않습니다.
- **실패·오류를 Toast 하나로만 알리지 마세요** — 사라지면 놓칩니다. 오류는 화면에 남는 Alert로.

**Alert (화면에 남는 안내 — 제목 + 설명 + 행동)**

```
[제목]  결제 정보 확인 필요
[설명]  카드 유효기간이 지났습니다. 결제 수단을 변경해 주세요.
[버튼]  결제 수단 변경
```

**Empty State (데이터 없는 화면)** — "없음"으로 끝내지 말고 다음 행동을 줍니다.

```
[제목]  등록된 거래처가 없습니다
[설명]  거래처를 추가하면 여기에서 관리할 수 있습니다.
[버튼]  거래처 추가
```

```
[검색 결과 없음]
“동화목재”에 대한 결과가 없습니다. 다른 검색어나 필터를 사용해 보세요.
```

**로딩** — 무엇을 기다리는지 밝힙니다.

```
❌ Loading... / 잠시만 기다려 주세요
✅ 주문 내역을 불러오는 중…
✅ 업로드 중 · 3/10개
```

**확인 다이얼로그 (파괴적 액션에만)**

```
[제목]  주문 3건을 삭제할까요?          ← 물음표, 개수·대상 명시
[본문]  삭제한 주문은 복구할 수 없습니다.  ← 영향 범위 + 복구 가능 여부
[버튼]  취소  |  삭제                   ← "예/아니요" 금지, 동사로
```

- 되돌릴 수 있는 작업이면 다이얼로그로 묻지 말고 **실행 후 "실행 취소" Toast**를 주세요.
- "정말로", "진짜" 같은 강조 부사 금지.

## 3.5 용어는 사전대로

같은 개념에 다른 단어를 쓰면 사용자는 다른 기능으로 오해합니다. 기획서 단계부터 표준 용어를 쓰세요.

| ✅ 표준 | ❌ 쓰지 않음 |
|--------|-------------|
| 로그인 | 사인인 · 접속 |
| 비밀번호 | 패스워드 · 암호 |
| 이메일 | 메일주소 |
| 설정 | 환경설정 · 세팅 |
| 알림 | 노티 · 푸시 |
| 저장 | 저장하기 · 세이브 |
| 삭제 | 제거 · 지우기 |
| 수정 | 편집 |
| 다시 시도 | 재시도 · 리트라이 |
| 자세히 보기 | 상세보기 · 디테일 |

새 용어가 필요하면 [writing.md §8 용어 사전](../foundations/writing.md)에 **먼저 등록하고** 사용합니다.

# SECTION 4. 품질 거버넌스 & 자가 검증 체크리스트

## 4.1 규칙을 어기면 어떻게 되나요 — 자동으로 걸러집니다

DDS 규칙은 "권장 사항"이 아니라 **검사 기준**입니다. 사람의 리뷰와 자동 검사가 이중으로 걸러냅니다.

| 관문 | 검사 내용 | 걸리면 | 상태 |
|------|----------|--------|------|
| **문구 리뷰** (PR·산출물 리뷰) | [라이팅 체크리스트](../foundations/writing-checklist.md) 기준 — "확인/예/아니오" 버튼, "오류가 발생했습니다" 단독, 이모지 등 **즉시 반려 목록** | **논의 없이 반려** | ✅ 운영 중 |
| **하드코딩 검사 CI** (PR 병합 전) | hex·rgb() 색상값, 간격 px, 이모지 문자를 자동 스캔 (`scripts/check_hardcoding.py`) | **검사 실패 — 병합 불가** | ✅ 운영 중 |
| **토큰 빌드 검증** (PR 병합 전) | 배포 토큰 파일(dist)이 토큰 원본(JSON)과 일치하는지 | 빌드 실패 — 병합 불가 | ✅ 운영 중 |
| **stylelint** (코드 저장 시) | 위 하드코딩 검사를 저장 시점에 미리 알림 | 저장 단계 오류 표시 | 🔜 도입 예정 |
| **i18n 키 검증** (PR 병합 전) | 하드코딩된 한글/영문 문구, 원문(ko) 누락, 한/영 변수 불일치 | 빌드 실패 또는 경고 | 🔜 도입 예정 |

> **핵심은 이것입니다** — 시안·기획서의 하드코딩 값과 비표준 문구는 개발 단계에서 자동으로 걸려 **병합되지 못합니다.**
> 선(先)적용하면 왕복이 없고, 후(後)수정하면 일정이 늘어납니다.
> 남은 자동화 일정은 [design.md 로드맵](../design.md) 참조.

## 4.2 DDS 자가 검증 체크리스트 — 기획·디자인 배포 전 5분

산출물(기획서·화면 정의서·시안)을 넘기기 전에 아래를 훑으세요. 전부 체크되면 개발 단계에서 반려될 일이 거의 없습니다.

### ① 내비게이션

- [ ] 내용이 다른 패널 전환은 **Tabs**, 보기 방식 전환은 **Segmented**로 구분했다
- [ ] 탭은 7개 이하다 (8개 이상이면 구조 재검토)
- [ ] Segmented 선택지는 4개 이하다 (5개 이상이면 Select)
- [ ] Breadcrumb는 3~4단계 이하이고, 마지막 항목은 링크가 아니다
- [ ] 모바일 화면 정의에 Breadcrumb 대신 **뒤로가기 버튼**을 지정했다
- [ ] 선택·현재 상태를 **색 하나로만** 표시하지 않았다 (색+굵기+표시선)
- [ ] 대량 목록에 Pagination 패턴(번호형/더 보기 등)과 페이지당 행 수를 지정했다
- [ ] 비활성(Disabled) 항목에는 이유 안내(툴팁 등)를 기획했다

### ② 스타일 · 아이콘

- [ ] 색상은 전부 **토큰 이름**으로 지정했다 (`#`으로 시작하는 값 없음)
- [ ] 간격·크기는 **spacing 토큰**(8의 배수)이다 (13px, 15px 같은 임의 수치 없음)
- [ ] 브랜드 초록은 **주요 액션에만** 썼고, 화면당 primary 버튼은 1개다
- [ ] UI에 **이모지가 하나도 없다** (아이콘은 라인 세트 이름으로 지정)
- [ ] 필요한 아이콘이 라이브러리에 없으면 임의로 만들지 않고 추가 요청했다
- [ ] 다크 모드에서 어떻게 보일지 확인했다 (토큰만 썼다면 자동 대응)

### ③ 문구 (UX 라이팅)

- [ ] 버튼이 **동사**다 (`확인`·`예`·`아니오` 없음)
- [ ] 오류 문구에 **[무슨 일] + [다음 행동]** 이 모두 있다
- [ ] 사용자를 탓하는 표현이 없다 (`잘못 입력하셨습니다` 금지)
- [ ] 입력 조건은 에러가 아니라 **헬퍼 텍스트로 먼저** 안내했다
- [ ] Empty State가 "없음"으로 끝나지 않고 다음 행동(버튼)을 준다
- [ ] 파괴적 액션 다이얼로그에 **개수·대상·복구 가능 여부**를 명시했다
- [ ] 제목·버튼·탭에 마침표가 없고, 느낌표는 어디에도 없다
- [ ] 같은 개념에 같은 단어를 썼다 (§3.5 용어 사전 기준)

### ④ 다국어 (한/영)

- [ ] 모든 문구에 한국어 원문이 있다 (영어 화면도 한국어 기준으로 먼저 작성)
- [ ] 버튼·라벨에 고정 폭을 지정하지 않았다 (영어 전환 시 최대 +80%)
- [ ] 이미지 안에 텍스트가 없다
- [ ] 날짜·통화가 §3.2 표기법을 따른다 (`2026. 6. 19.` · `₩1,234,000`)
- [ ] 문장을 반쪽으로 쪼개 조립하는 구조가 없다

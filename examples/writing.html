UX 라이팅 샘플 — 거래처 관리

하나의 화면에서 벌어지는 5가지 상황을 규칙 위반 ↔ DDS 적용으로 비교합니다.
규범 문서: writing.md · i18n.md

언어 토글은 오른쪽 DDS 적용 패널에만 적용됩니다. 왼쪽은 안티패턴 예시라 번역 대상이 아닙니다.

1

거래처 목록이 비어 있다

첫 진입 사용자가 가장 먼저 보는 화면. 여기서 다음 행동을 못 찾으면 이탈한다.

규칙 위반

데이터 없음

  • 상태만 알리고 다음 행동이 없다
  • "데이터"는 시스템의 단어이지 사용자의 단어가 아니다
DDS 적용

등록된 거래처가 없습니다

거래처를 추가하면 주문·정산 내역을 한곳에서 관리할 수 있습니다.

  • 제목은 상황, 설명은 이유·이득, 버튼은 다음 행동
  • 제목에 마침표 없음 · 설명은 서술문이라 마침표 있음

적용 규칙 · writing.md §6(Empty State 패턴) · §4.1(동사 라벨) · §3.2(마침표)

2

거래처 등록 폼에서 입력이 틀렸다

오류 문구는 "무엇이 문제인지"가 아니라 "무엇을 하면 되는지"를 말해야 한다.

규칙 위반

입력값이 잘못되었습니다.

  • 라벨 없이 placeholder로 대체 — 입력하면 라벨이 사라진다
  • "잘못되었습니다"는 사용자를 탓하고, 고칠 방법을 안 준다
  • "확인"은 눌렀을 때 무슨 일이 생기는지 알려주지 않는다
DDS 적용
입력값 2개를 확인해 주세요
  • 담당자 이메일 — 형식을 확인해 주세요
  • 사업자등록번호 — 10자리 숫자를 입력해 주세요

이메일 형식을 확인해 주세요.

하이픈 없이 10자리 숫자로 입력해 주세요

  • 폼 상단에 요약 Alert, 각 필드에 구체적 지시 — 3계층 중 2개 층 사용
  • 사업자등록번호는 Helper로 미리 조건을 알려 오류 자체를 예방
  • 버튼이 "확인"이 아니라 "거래처 등록" — 결과를 예측할 수 있다

적용 규칙 · writing.md §5.1(무슨 일+어떻게) · §5.2(3계층) · §5.3(표준 문안) · §6(Helper 우선) · §4.2(라벨)

3

거래처 3곳을 삭제하려 한다

되돌릴 수 없는 액션에만 다이얼로그를 쓴다. 되돌릴 수 있으면 실행 후 "실행 취소"를 준다.

규칙 위반

경고!

정말로 삭제하시겠습니까? 삭제된 데이터는 영구히 파괴됩니다.

  • "경고!" — 느낌표로 겁을 주지만 정보는 없다
  • 무엇이 몇 개 삭제되는지 안 밝힌다
  • "예/아니오"는 질문을 다시 읽어야 뜻을 안다
  • "영구히 파괴" — 공포 조성 표현
DDS 적용

거래처 3곳을 삭제할까요?

삭제한 거래처의 주문 이력은 복구할 수 없습니다.

  • 제목이 개수를 포함한 질문 — 물음표는 여기서만 쓴다
  • 본문은 복구 가능 여부만 사실대로
  • 버튼이 제목의 질문에 동사로 답한다

적용 규칙 · writing.md §7(다이얼로그 구조) · §4.3(버튼 쌍) · §2(톤) · §3.2(물음표)

4

삭제 결과를 알린다

성공은 사라져도 되지만, 실패는 사라지면 안 된다.

규칙 위반
처리에 실패하였습니다.
  • 무엇이 실패했는지, 이제 뭘 해야 하는지 없다
  • 시스템 오류를 4초 뒤 사라지는 Toast로만 알린다 — 놓치면 끝
  • 재시도 경로가 없다
DDS 적용

성공 — 일시 Toast + 되돌리기

거래처 3곳을 삭제했습니다.

실패 — 지속 Inline Alert + 재시도

거래처를 삭제하지 못했습니다 일시적인 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. 오류 코드: DW-5021
  • 성공은 Toast + 실행 취소, 실패는 Inline Alert + 다시 시도로 분리
  • 오류 코드는 문장 안이 아니라 별도 줄 보조 텍스트로
  • Toast 서술문에는 마침표, 액션 버튼 라벨에는 없음

적용 규칙 · writing.md §6(컴포넌트별 패턴) · §5.2(시스템 계층) · §5.3(서버 오류 표준 문안)

5

목록을 불러오는 중이다

로딩 문구도 문구다. 무엇을 기다리는지 밝힌다.

규칙 위반
Loading...
  • 번역되지 않은 영문 + 무엇을 기다리는지 없음
  • 말줄임표를 마침표 3개로 대체
DDS 적용
거래처 목록을 불러오는 중…
  • 대상을 밝히고 진행형으로 쓴다
  • 말줄임표는 …(U+2026) 하나
  • 0.3초 이상 걸릴 때만 노출 (깜빡임 방지)

적용 규칙 · writing.md §6(로딩) · §3.2(말줄임표) · feedback.md §4

6

같은 화면을 영어로 낸다

한국어는 짧다. 번역하면 버튼이 먼저 깨진다.

문자열 키 · ICU 복수형

위 ③ 다이얼로그의 실제 리소스. 개수는 변수로, 복수형은 ICU로 처리한다.

// locales/ko-KR/vendor.json
{
  "vendor.delete.title": "거래처 {count}곳을 삭제할까요?",
  "vendor.delete.success": "거래처 {count}곳을 삭제했습니다."
}

// locales/en-US/vendor.json
{
  "vendor.delete.title": "{count, plural,
     one {Delete this vendor?}
     other {Delete # vendors?}}",
  "vendor.delete.success": "{count, plural,
     one {# vendor deleted.}
     other {# vendors deleted.}}"
}
  • 금지 — t('prefix') + count + t('suffix') 방식은 어순이 다른 언어에서 무너진다
  • 한국어는 복수 표지가 없어 단일 문안, 영어는 one/other 분기

적용 규칙 · i18n.md §2(키 네이밍) · §4(조립 금지) · §5.2(ICU plural)

라벨 길이 확장 — 실측

지금 이 브라우저에서 잰 텍스트 렌더 폭입니다. 글자 수는 2~3배로 늘어도 폭은 그만큼 늘지 않습니다 — 한글 1자가 라틴 1.7~1.8자만큼 넓기 때문입니다.

한국어English글자 수렌더 폭폭 증가
  • 2자 라벨이 가장 위험하다 — 취소 → Cancel은 폭이 80% 늘어난다
  • 반대로 내보내기 → Export는 오히려 짧아진다. 글자 수만 보면 판단할 수 없다
  • 문장은 폭보다 줄 수가 는다 — 영어는 단어 단위로만 줄바꿈되기 때문
  • 버튼에 고정 width 금지 — min-width + 패딩으로만

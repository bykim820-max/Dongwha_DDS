# Internationalization (i18n)

> 다국어는 번역 작업이 아니라 **설계 제약**이다. 문자열·레이아웃·형식이 처음부터 로케일에 열려 있어야
> 언어를 추가할 때 UI를 다시 만들지 않는다. 문안 자체의 규칙은 → [writing.md](./writing.md)

[← design.md](../design.md) · 라이팅 → [writing.md](./writing.md) · 실제 화면 샘플 → [examples/writing.html](../examples/writing.html)

---

## 1. 지원 로케일

| 로케일 | 역할 | 상태 |
|--------|------|------|
| `ko-KR` | **원문 SSOT** — 모든 문구의 기준 | 지원 |
| `en-US` | 번역 대상 | 지원 |
| 그 외 | 아래 규칙을 따라 추가 | 확장 가능 |

**Fallback 체인**: `요청 로케일` → `ko-KR` → **키 노출 금지**

```
ko-KR 없음                → 빌드 실패 (원문 누락은 버그)
en-US 없음                → ko-KR 표시 + 경고 로그
어느 쪽도 없음(잘못된 키)  → 빌드 실패. 화면에 키 문자열을 절대 노출하지 않는다
```

- 로케일 판별 순서: 사용자 설정 → 계정 기본값 → `navigator.language` → `ko-KR`
- 언어 전환은 **새로고침 없이** 적용되어야 한다(문자열은 런타임 조회).

## 2. 문자열 키 네이밍

```
<domain>.<component>.<element>[.<state>]
```

| 예시 키 | 값(ko) |
|---------|--------|
| `common.action.save` | 저장 |
| `common.action.cancel` | 취소 |
| `order.list.empty.title` | 등록된 주문이 없습니다 |
| `order.detail.button.delete` | 삭제 |
| `error.network.offline` | 네트워크에 연결되어 있지 않습니다. 연결을 확인한 뒤 다시 시도해 주세요. |
| `field.email.helper` | 회사 이메일을 입력해 주세요 |

**규칙**

1. 소문자 + 점(`.`) 구분. 단어 연결은 하이픈(`order-detail`)
2. **키에 문안을 넣지 않는다** — ❌ `btn.저장`, ❌ `msg.save-success-저장했습니다`
3. 2개 이상 화면에서 쓰는 문구는 `common.*`으로 승격
4. 오류는 `error.<도메인>.<유형>`으로 모아 §5.3 표준 문안과 1:1 매핑 → [writing.md §5.3](./writing.md)
5. 키는 **삭제하지 말고 deprecate** 표시 후 한 릴리스 뒤 제거(번역 유실 방지)

**파일 구조**

```
locales/
├── ko-KR/
│   ├── common.json
│   ├── order.json
│   └── error.json
└── en-US/
    ├── common.json
    ├── order.json
    └── error.json
```

## 3. 문자열 확장 · 레이아웃

번역하면 **글자 수는 크게 늘지만 렌더 폭은 그만큼 늘지 않는다.** 한글 1자가 라틴 1.7~1.8자만큼 넓기 때문이다.
레이아웃을 잡을 때 기준으로 삼아야 하는 것은 글자 수가 아니라 **폭**이다.

실측 기준 — Pretendard 14px / weight 500 ([examples/writing.html](../examples/writing.html) §6에서 실시간 측정):

| 한국어 원문 | 글자 수 증가 | **렌더 폭 증가** | 예 |
|-------------|-------------|-----------------|-----|
| **2자 라벨** | +100~200% | **+28~80%** ← 가장 위험 | 저장 → Save (+28%) · 취소 → Cancel (+80%) |
| 3~6자 라벨 | +50~100% | +15~25% (짧아지기도 함) | 다시 시도 → Try again (+15%) · 내보내기 → Export (**−12%**) |
| 15자 이상 문장 | +65~75% | +10~20% | 오류·설명 문장 |

> **2자 버튼**(저장·취소·삭제·확인)이 가장 크게 늘어난다. 라벨이 짧을수록 위험하다.
> 반대로 **문장은 폭보다 줄 수**가 문제다 — 영어는 단어 단위로만 줄바꿈되므로 좁은 컨테이너에서 줄이 늘어난다.

**레이아웃 규칙**

- 버튼·라벨에 **고정 `width` 금지**. `min-width` + 내부 패딩(`spacing/*`)으로만 크기를 잡는다
  - `min-width: 64px` 버튼은 "Cancel"에서 **약 77px로 늘어난다.** 늘어나는 것이 정상이고, `width: 64px`이면 잘린다
- 텍스트 컨테이너는 **2줄까지 늘어날 수 있다**고 가정하고 세로 정렬을 설계한다
- 잘림이 불가피한 곳(테이블 셀·칩)은 `text-overflow: ellipsis` + 전체 문구를 `title` 속성으로 제공
- 아이콘 + 라벨 조합은 아이콘 크기 고정, 라벨만 신축
- **의사 로컬라이제이션**(`[[저장 ~~~~]]`)으로 최장 케이스를 렌더 테스트한다

```css
.btn {
  min-width: 64px;          /* ✅ 최소폭만 */
  padding: 0 var(--space-16);
  white-space: nowrap;      /* 라벨은 줄바꿈 금지, 대신 컨테이너가 늘어남 */
}
.cell {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;      /* + title 속성으로 전체 문구 제공 */
}
```

## 4. 하드코딩 · 문장 조립 금지

```tsx
// ❌ 하드코딩
<Button>저장</Button>

// ✅ 키 조회
<Button>{t('common.action.save')}</Button>
```

```tsx
// ❌ 문장 조립 — 언어마다 어순이 다르므로 번역이 불가능하다
t('order.prefix') + count + t('order.suffix')
`${name}님의 ` + t('order.list')

// ✅ 하나의 문장 = 하나의 키 + 명명된 변수
t('order.count', { count })          // ko: 주문 {count}건
t('order.owner', { name })           // ko: {name}님의 주문
```

**번역 대상에 포함해야 하는 것**

- 화면 텍스트, 버튼 라벨, 헬퍼·에러 문구
- `aria-label` · `alt` · `title` · `placeholder`
- 이메일·알림 템플릿, PDF·엑셀 내보내기 헤더
- 날짜·통화 **형식**(값이 아니라 형식 자체)

## 5. 변수 · 복수형

### 5.1 변수(플레이스홀더)

- **명명된 변수만** 사용: `{count}`, `{name}` — 위치 인자 `{0}` 금지(어순 변경에 취약)
- 변수는 문장 어디에나 올 수 있다고 가정한다(한국어 어순 ≠ 영어 어순)
- 사용자 입력 값을 넣을 때는 **이스케이프** 후 삽입
- 변수 하나에 문장을 통째로 넣지 않는다 — ❌ `{message}` 안에 다른 번역문 주입

### 5.2 복수형 (ICU MessageFormat)

한국어는 복수 표지가 없어 `one`과 `other`가 같지만, **영어는 반드시 분기**한다.

```json
// ko-KR/order.json
{ "order.count": "주문 {count}건" }

// en-US/order.json
{ "order.count": "{count, plural, one {# order} other {# orders}}" }
```

```json
// 0건은 별도 문안이 자연스러운 경우
{ "order.count": "{count, plural, =0 {No orders} one {# order} other {# orders}}" }
```

- 숫자와 단위를 **직접 이어붙이지 않는다** — ❌ `count + t('unit.case')`
- 선택·성별에 따른 분기는 `{gender, select, ...}` 사용

## 6. 톤의 언어별 차이

같은 키라도 언어별 관용에 맞춘다. **직역하지 않는다.**

| 항목 | ko-KR | en-US |
|------|-------|-------|
| 요청 어미 | 존댓말 `~해 주세요` | 명령형 평서 — `Enter your email` |
| 결과 알림 | `저장했습니다.` | `Saved.` (짧게) |
| 주어 | 생략 | `you / your` 최소한으로만 |
| 대소문자 | 해당 없음 | **Sentence case** — 버튼·제목 포함 (`Save changes`, ❌ `Save Changes`) |
| 축약형 | 해당 없음 | 자연스러운 축약 허용 (`don't`, `can't`) |
| 마침표 | 서술문에만 → [writing.md §3.2](./writing.md) | 동일 규칙 적용 |
| 오류 주체 | 주체 생략 | 시스템 귀책은 `we` (`We couldn't save your changes.`) |

## 7. 날짜 · 숫자 · 통화

**저장은 ISO 8601 + UTC, 표시만 로컬.** 포맷은 반드시 `Intl` API로 처리하고 수동 문자열 조합을 금지한다.

| 항목 | ko-KR | en-US |
|------|-------|-------|
| 날짜(문장) | 2026. 6. 19. | Jun 19, 2026 |
| 날짜(데이터) | 2026-06-19 | 2026-06-19 |
| 날짜+시간 | 2026. 6. 19. 오후 3:24 | Jun 19, 2026, 3:24 PM |
| 요일 | (금) | Fri |
| 숫자 | 1,234,567 | 1,234,567 |
| 소수 | 1,234.56 | 1,234.56 |
| 퍼센트 | 24.5% | 24.5% |
| 통화(원) | ₩1,234,000 | KRW 1,234,000 |
| 통화(달러) | US$1,234.00 | $1,234.00 |
| 파일 크기 | 20MB | 20 MB (숫자와 단위 사이 공백) |

```ts
new Intl.DateTimeFormat(locale, { dateStyle: 'long', timeStyle: 'short', timeZone: tz }).format(d);
new Intl.NumberFormat(locale, { style: 'currency', currency: 'KRW' }).format(1234000);
new Intl.RelativeTimeFormat(locale, { numeric: 'auto' }).format(-3, 'day');  // 3일 전 / 3 days ago
```

**규칙**

- 서버·API 교환은 항상 **UTC ISO 8601**(`2026-06-19T06:24:00Z`). 로컬 변환은 표시 계층에서만
- 사용자 타임존을 명시적으로 저장하고, 다른 타임존 값 표시 시 타임존을 함께 노출
- 큰 수 축약(`1.2만`·`1.2K`)은 **차트 축·요약 카드에만** 허용. 표·금액·수량에는 전체 숫자를 쓴다
- 정렬은 문자열 비교 대신 `Intl.Collator(locale)` 사용

### 7.1 이름 · 주소 · 전화

- 성명은 **단일 필드**(`fullName`)를 기본으로 한다. 성/이름 분리를 강요하지 않는다
- 주소 폼의 **필드 순서·필수 여부는 로케일별로 다르다**. 한국식 순서를 고정하지 않는다
- 전화번호는 국가번호를 포함해 저장(`+82-10-...`), 표시만 로컬 포맷
- 이름·주소 필드에 정규식으로 한글만 허용하는 검증을 걸지 않는다

## 8. 타이포그래피 · 줄바꿈

- 폰트는 **Pretendard 단일**(한글·라틴 동시 커버) → [typography.md](./typography.md)
- 한국어 본문에는 **어절 단위 줄바꿈**을 적용한다

```css
:lang(ko) { word-break: keep-all; overflow-wrap: break-word; }
:lang(en) { word-break: normal;   overflow-wrap: break-word; }
.token    { overflow-wrap: anywhere; }  /* URL·ID 등 긴 무공백 문자열 */
```

- 루트와 언어 전환 지점에 **`lang` 속성 필수** — 스크린리더 발음과 하이픈 규칙에 영향
- 숫자 + 단위, 금액 + 통화 기호 사이 줄바꿈 금지
- 줄바꿈 위치를 `<br>`로 고정하지 않는다(번역 시 깨짐)
- 향후 RTL 확장을 위해 물리 속성 대신 **논리 속성**을 쓴다: `margin-inline-start`, `padding-inline`, `text-align: start`

## 10. 개발 체크리스트

**구현 시**

- [ ] UI 문자열에 하드코딩이 없다(`aria-label`·`alt`·`placeholder` 포함)
- [ ] 문장을 `+`로 조립하지 않았다
- [ ] 수량 표현에 ICU plural을 사용했다
- [ ] 날짜·숫자·통화를 `Intl`로 포맷했다
- [ ] 고정 `width` 없이 최장 번역문에서 레이아웃이 깨지지 않는다
- [ ] `lang` 속성과 `word-break` 규칙이 적용됐다
- [ ] **텍스트가 이미지에 포함되어 있지 않다**(아이콘은 라인 SVG만)

**CI 검증**

| 검사 | 실패 조건 |
|------|-----------|
| 원문 누락 | `ko-KR`에 없는 키를 참조 |
| 키 미사용 | 어느 코드에서도 참조되지 않는 키(경고) |
| 변수 불일치 | 로케일 간 플레이스홀더 집합이 다름 |
| 하드코딩 | 컴포넌트에서 한글·영문 리터럴 직접 렌더 |
| 길이 초과 | 번역문이 [writing.md §3.3](./writing.md) 상한 초과(경고) |

## 11. LLM i18n 적용 우선순위

코드·문구 생성 시 다음 순서로 적용한다.

1. **문자열은 키로 출력** — 하드코딩 대신 `t('<domain>.<component>.<element>')` (§2)
2. **문장 단위로 하나의 키** — 조립·연결 금지 (§4)
3. **수량이 들어가면 ICU plural** (§5.2)
4. **날짜·숫자·통화는 `Intl`** — 수동 포맷 금지 (§7)
5. **레이아웃은 신축 전제** — 고정 폭 금지, `min-width`만 (§3)
6. **`lang` 속성 · `word-break: keep-all`** 포함 (§8)
7. **ko/en 문안을 함께 생성**하되 직역하지 않고 §6 톤 규칙을 적용, 용어는 §9 대응표를 따른다

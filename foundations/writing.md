# UX Writing

> 문구는 **눈에 보이는 인터페이스**다. 좋은 UX 라이팅의 목적은 사용자가 **읽지 않고도 이해**하고,
> 막혔을 때 **다음에 할 일을 알게** 하는 것. 화려한 표현보다 **정확하고 짧고 사람의 말**이 우선이다.

[← design.md](../design.md) · 다국어 → [i18n.md](./i18n.md) · 실제 화면 샘플 → [examples/writing.html](../examples/writing.html)

> **리뷰할 때는 이 문서 대신 [체크리스트](./writing-checklist.md) 한 장을 쓴다.** 이 문서는 근거와 표를 담은 규범서다.

---

## 1. 라이팅 원칙

| 원칙 | 의미 |
|------|------|
| **Clear** (명확) | 한 번 읽고 이해된다. 전문 용어·내부 용어 대신 사용자의 단어를 쓴다 |
| **Concise** (간결) | 빼도 뜻이 통하는 단어는 뺀다. 라벨 1~2어절, 설명 1~2문장 |
| **Useful** (유용) | 상태만 알리지 않고 **다음 행동**을 준다. "실패"로 끝내지 않는다 |
| **Human** (사람다움) | 시스템 관점이 아닌 사용자 관점. 기계어(`null`·`Exception`) 노출 금지 |
| **Respectful** (존중) | 사용자를 탓하지 않는다. 겁주지 않는다. 농담으로 얼버무리지 않는다 |
| **Consistent** (일관) | 같은 개념은 항상 같은 단어로. §8 용어 사전이 기준 |

> 문구도 토큰처럼 다룬다. 같은 상황에는 **같은 문안 패턴**을 재사용하고, 화면마다 새로 짓지 않는다.

## 2. 보이스 & 톤

**보이스**(정체성)는 항상 고정 — *정중하고 담백한 실무 동료*.
**톤**(상황별 온도)만 변한다.

| 상황 | 톤 | 예 |
|------|-----|-----|
| 일반 안내 | 중립·담백 | 변경 사항은 자동으로 저장됩니다. |
| 작업 성공 | 짧게 사실만 | 저장했습니다. |
| 입력 오류 | 차분·해결 지향 | 이메일 형식을 확인해 주세요. |
| 시스템 오류 | 침착·책임 있는 | 일시적인 문제로 불러오지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 파괴적 액션 | 단호·구체적 | 주문 3건을 삭제합니다. 삭제 후에는 복구할 수 없습니다. |
| 빈 화면 | 안내·유도 | 아직 등록된 거래처가 없습니다. |

- 성공에 과장(“완벽하게 저장되었습니다!”) 금지, 오류에 사과 남발(“정말 죄송합니다”) 금지.
- 감정 표현·의성어(“앗!”, “이런!”)와 **이모지는 금지** → [design.md § 디자인 금지 규칙](../design.md#-디자인-금지-규칙-anti-patterns)

## 3. 문장 기본 규칙 (한국어)

### 3.1 종결 어미

| 유형 | 어미 | 예 |
|------|------|-----|
| 결과·완료 알림 | `~했습니다` | 삭제했습니다. |
| 상태·사실 설명 | `~합니다` / `~입니다` | 30일간 보관됩니다. |
| 행동 요청·유도 | `~해 주세요` | 파일을 선택해 주세요. |
| 라벨·제목·버튼 | 명사형 / 동사 어간 | 저장 · 주문 내역 · 결제하기 |

- ❌ `~하십시오`(고압적) · ❌ `~해요`체(가벼움) · ❌ `~하시기 바랍니다`(장황)
- 보조용언은 띄어 쓴다: **“해 주세요”** (`해주세요` 아님)

### 3.2 문장부호

| 부호 | 규칙 |
|------|------|
| 마침표 `.` | **완전한 서술문에만** — 헬퍼·에러·설명·토스트 본문 |
| 마침표 없음 | 제목 · 버튼 라벨 · 메뉴 · 탭 · 툴팁 · 테이블 헤더 · 배지 · 1~2어절 상태 |
| 느낌표 `!` | 원칙적으로 사용 안 함 |
| 물음표 `?` | 확인 다이얼로그 **제목**에만 |
| 말줄임표 | `…`(U+2026) 하나만. `...` 금지 |
| 따옴표 | 사용자 데이터 인용 시 `“ ”` — 예: “2026 예산안”을 삭제합니다 |

### 3.3 길이

| 요소 | 권장 | 상한 |
|------|------|------|
| 버튼 라벨 | 2~6자 | 12자 |
| 필드 라벨 | 2~8자 | 15자 |
| 헬퍼 텍스트 | 1문장 | 40자 |
| 에러 메시지 | 1~2문장 | 60자 |
| 툴팁 | 1문장 | 30자 |
| 토스트 | 1문장 | 40자 |
| Empty State 설명 | 1~2문장 | 80자 |

### 3.4 숫자 · 단위 · 날짜

- 천 단위 콤마: `1,234,567`
- 수량 단위는 붙여 쓴다: `3건` · `12개` · `5MB`
- 날짜 표기: `2026. 6. 19.` (문장 내) · `2026-06-19` (테이블·로그)
- 시간: `오후 3:24`
- 금액: `₩1,234,000` — 통화 기호와 숫자 사이 공백 없음
- 숫자와 단위 사이는 **줄바꿈 금지** (`<span class="nowrap">`)
- 로케일별 형식은 → [i18n.md §7](./i18n.md)

## 4. 버튼 · 액션 라벨

### 4.1 규칙

1. **동사로 쓴다.** 누르면 무슨 일이 일어나는지 라벨만 보고 알 수 있어야 한다.
2. **다이얼로그 제목의 질문에 답하는 동사**를 쓴다. “확인/취소” 쌍은 되도록 피한다.
3. **대상을 밝힌다.** 위험한 액션일수록 구체적으로: `삭제` → `주문 3건 삭제`
4. **primary는 화면당 1개.** 나머지는 secondary·tertiary → [button.md §3](../components/button.md)
5. **로딩 중에는 진행형**으로 바꾼다: `저장` → `저장 중…` (`aria-busy="true"` 동반)
6. **아이콘 전용 버튼은 `aria-label`에 같은 규칙**을 적용한다.

### 4.2 표준 라벨

| 상황 | ✅ 권장 | ❌ 지양 |
|------|--------|--------|
| 폼 제출 | 저장 · 등록 · 제출 | 확인 · OK |
| 삭제 확인 | 삭제 · 영구 삭제 | 예 · 확인 |
| 취소·되돌리기 | 취소 · 실행 취소 | 아니요 · 닫기(의미 다름) |
| 창 닫기 | 닫기 | 취소 |
| 다음 단계 | 다음 · 계속 | 진행 |
| 재시도 | 다시 시도 | 재시도하기 · 리트라이 |
| 상세 이동 | 자세히 보기 | 더보기(목록 확장과 혼동) |
| 목록 더 불러오기 | 더 보기 | 자세히 |
| 파일 | 파일 선택 · 내보내기 · 가져오기 | 업로드하기 · 다운받기 |
| 로그인 | 로그인 | 로그인 하기 · 사인인 |

### 4.3 버튼 쌍 예시

```tsx
// ❌ 무엇이 삭제되는지 라벨이 말해주지 않는다
<ButtonStack align="end" gap="12">
  <Button variant="tertiary">아니요</Button>
  <Button variant="danger">예</Button>
</ButtonStack>

// ✅ 제목의 질문에 동사로 답한다
<ButtonStack align="end" gap="12">
  <Button variant="tertiary">취소</Button>
  <Button variant="danger">삭제</Button>
</ButtonStack>
```

## 5. 오류 메시지

### 5.1 3요소 구조

```
[무슨 일]  일어난 사실을 사용자 언어로
[왜]       필요할 때만. 원인이 행동을 바꿀 때만 쓴다
[어떻게]   다음에 할 행동 — 가능하면 실행 가능한 액션으로
```

> 최소 요건은 **[무슨 일] + [어떻게]**. 둘 중 하나라도 빠지면 반려한다.

```
❌ 오류가 발생했습니다.
❌ 입력값이 잘못되었습니다. (사용자 탓 + 무엇이 잘못인지 없음)
✅ 파일을 업로드하지 못했습니다. 20MB 이하 파일만 첨부할 수 있습니다.
```

### 5.2 3계층 배치

| 계층 | 위치 | 컴포넌트 | 문안 성격 |
|------|------|----------|-----------|
| **필드** | 해당 입력 바로 아래 | Input `errorText` | 그 필드만 고치는 짧은 지시 |
| **폼·영역** | 폼 상단 | Inline Alert (`danger`) | 여러 필드 요약 + 첫 오류로 포커스 이동 |
| **시스템** | 화면 단위 | Inline Alert / Empty State | 재시도·문의 경로 제공 |

- 시스템 오류를 **Toast 단독**으로 알리지 않는다(놓친다) → [feedback.md §2](../components/feedback.md)
- 에러는 **색만으로 표시 금지** — 보더 + 라인 아이콘 + 텍스트 3중 표시
- `aria-invalid="true"` + `aria-describedby` + `role="alert"` 필수 → [input.md §8](../components/input.md)

### 5.3 표준 오류 문안

| 유형 | 한국어 | English |
|------|--------|---------|
| 필수 미입력 | 이메일을 입력해 주세요. | Enter your email. |
| 형식 오류 | 이메일 형식을 확인해 주세요. | Enter a valid email address. |
| 길이 미달 | 비밀번호는 8자 이상이어야 합니다. | Password must be at least 8 characters. |
| 범위 초과 | 1~100 사이의 숫자를 입력해 주세요. | Enter a number between 1 and 100. |
| 중복 | 이미 사용 중인 아이디입니다. | This ID is already taken. |
| 불일치 | 비밀번호가 일치하지 않습니다. | Passwords don't match. |
| 인증 실패 | 아이디 또는 비밀번호를 확인해 주세요. | Check your ID or password. |
| 세션 만료 | 로그인이 만료되었습니다. 다시 로그인해 주세요. | Your session expired. Log in again. |
| 권한 없음 | 이 항목에 접근할 권한이 없습니다. 관리자에게 문의해 주세요. | You don't have access to this item. Contact your administrator. |
| 없는 리소스 | 요청한 페이지를 찾을 수 없습니다. | We couldn't find that page. |
| 네트워크 | 네트워크에 연결되어 있지 않습니다. 연결을 확인한 뒤 다시 시도해 주세요. | You're offline. Check your connection and try again. |
| 시간 초과 | 응답 시간이 초과되었습니다. 다시 시도해 주세요. | The request timed out. Try again. |
| 서버 오류 | 일시적인 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. | Something went wrong on our end. Try again in a moment. |
| 용량 초과 | 20MB 이하 파일만 첨부할 수 있습니다. | Files must be 20 MB or smaller. |
| 미지원 형식 | PDF·JPG·PNG 파일만 첨부할 수 있습니다. | You can attach PDF, JPG, or PNG files. |
| 저장 실패 | 저장하지 못했습니다. 다시 시도해 주세요. | We couldn't save your changes. Try again. |

- 지원 문의가 필요한 시스템 오류만 **오류 코드**를 보조 텍스트(`Color/text/tertiary`)로 덧붙인다: `오류 코드: DW-5021`
- 코드는 문장 안이 아니라 **문장 뒤 별도 줄**에 둔다.

### 5.4 금지

```
❌ 잘못된 값을 입력하셨습니다        → 사용자를 탓함
❌ Error: NullPointerException      → 기계어 노출
❌ 처리에 실패하였습니다             → 무엇을·어떻게가 없음
❌ 데이터가 영구히 파괴됩니다        → 공포 조성
❌ 앗! 문제가 생겼어요 😅            → 농담 + 이모지
```

## 6. 안내 · 상태 문구

| 컴포넌트 | 문안 패턴 | 예 |
|----------|-----------|-----|
| **Toast** (성공) | 무엇을 + 완료 | 저장했습니다. / 주문 3건을 삭제했습니다. |
| **Toast** (되돌리기) | 결과 + 액션 버튼 | 삭제했습니다. **[실행 취소]** |
| **Inline Alert** | 제목(요약) + 설명(행동) | **결제 정보 확인 필요** · 카드 유효기간이 지났습니다. 결제 수단을 변경해 주세요. |
| **Empty State** | 제목(상황) + 설명(이유·다음) + 액션 | **등록된 거래처가 없습니다** · 거래처를 추가하면 여기에서 관리할 수 있습니다. **[거래처 추가]** |
| **검색 결과 없음** | 검색어 인용 + 대안 | “동화목재”에 대한 결과가 없습니다. 다른 검색어나 필터를 사용해 보세요. |
| **Tooltip** | 명사구·짧은 설명, 마침표 없음 | 최근 30일 기준 |
| **Helper Text** | 입력 **전**에 조건 안내 | 영문·숫자 조합 8자 이상 |
| **Placeholder** | 예시 값만 | name@example.com |
| **로딩** | 진행 중인 대상 명시 | 주문 내역을 불러오는 중… |
| **Progress** | 진행 상태 + 수치 | 업로드 중 · 3/10개 |

### 6.1 규칙

- **Helper로 먼저, Error로 나중에.** 조건은 입력 전에 알린다. 에러로만 알리면 실패를 유도한 셈이다.
- **Placeholder는 라벨을 대체하지 않는다.** 라벨은 항상 별도 표시 → [input.md §9](../components/input.md)
- **Empty State는 “없음”으로 끝내지 않는다.** 빈 이유 + 채우는 방법을 함께 준다.
- **로딩 문구는 0.3초 이상**일 때만 노출한다(깜빡임 방지) → [feedback.md §4](../components/feedback.md)
- 성공 Toast에 마침표를 쓰고, 함께 놓인 **액션 버튼 라벨에는 쓰지 않는다**.

## 7. 확인 다이얼로그

파괴적·비가역 액션에만 쓴다. 되돌릴 수 있으면 **다이얼로그 대신 실행 후 “실행 취소” Toast**를 준다.

```
제목    되돌릴 수 없는 결과를 담은 질문 — 물음표 사용
본문    영향 범위(개수·대상) + 복구 가능 여부
버튼    [취소]  [구체적 동사]
```

```tsx
// 제목: 주문 3건을 삭제할까요?
// 본문: 삭제한 주문은 복구할 수 없습니다.
<ButtonStack align="end" gap="12">
  <Button variant="tertiary">취소</Button>
  <Button variant="danger">삭제</Button>
</ButtonStack>
```

- 본문에서 **개수·대상을 반드시 명시**한다. “선택한 항목” 대신 “주문 3건”.
- “정말로”, “진짜” 같은 강조 부사는 쓰지 않는다.

## 8. 용어 사전

같은 개념에는 항상 같은 단어를 쓴다. 신규 용어는 이 표에 추가한 뒤 사용한다.

| 표준 | 쓰지 않음 |
|------|-----------|
| 로그인 · 로그아웃 | 사인인 · 사인아웃 · 접속 |
| 비밀번호 | 패스워드 · 암호 |
| 이메일 | 메일주소 · 이메일주소 |
| 계정 | 어카운트 · 아이디(계정 전체를 뜻할 때) |
| 설정 | 환경설정 · 세팅 |
| 알림 | 노티 · 푸시 |
| 저장 | 저장하기 · 세이브 |
| 삭제 | 제거 · 지우기 |
| 수정 | 편집 · 변경(값 자체를 바꿀 때만 “변경”) |
| 추가 | 등록(신규 생성 절차가 있을 때만 “등록”) |
| 불러오기 | 로드 · 조회 |
| 내보내기 · 가져오기 | 다운로드 · 업로드(파일 전송 자체를 말할 때만) |
| 다시 시도 | 재시도 · 리트라이 |
| 자세히 보기 | 상세보기 · 디테일 |
| 첨부 | 파일 첨부하기 |
| 필수 · 선택 | 필수값 · 옵션 |

- 영어 대응은 → [i18n.md §9](./i18n.md)

## 9. Do / Don't

✅ **DO**
- 라벨은 동사, 설명은 문장, 제목은 명사구
- 오류에는 **다음 행동**을 반드시 포함
- 개수·대상 등 **구체적인 수치**를 밝힌다
- 조건은 입력 **전에** Helper로 안내
- 같은 개념은 §8 용어 사전의 단어로 통일
- 문구 변경 시 [i18n.md](./i18n.md) 키·번역도 함께 갱신

❌ **DON'T**
- “확인 / 예 / OK” 같은 모호한 버튼 라벨
- “오류가 발생했습니다” 단독 노출
- 사용자를 탓하는 표현(“잘못 입력하셨습니다”)
- 기술 용어·스택 트레이스·HTTP 코드 원문 노출
- 이모지·느낌표·의성어
- 라벨 자리에 문장, 문장 자리에 단어
- 이미지 안에 텍스트 넣기(번역 불가) → [i18n.md §10](./i18n.md)

## 10. LLM 라이팅 적용 우선순위

문구를 생성·수정할 때 다음 순서로 판단한다.

1. **용어** — §8 사전에 있는 개념인가? 있으면 사전 표기를 그대로 쓴다
2. **요소 종류 판별** — 버튼/에러/안내 중 무엇인가? → §4 / §5 / §6의 패턴을 따른다
3. **에러라면** — §5.1의 [무슨 일] + [어떻게]가 모두 있는가? 없으면 보완
4. **어미·문장부호** — §3.1 어미표, §3.2 마침표 규칙 적용
5. **길이** — §3.3 상한 초과 시 문장을 줄이거나 두 요소로 분리
6. **금지 표현 검사** — §5.4 · §9의 ❌ 항목이 남아 있는지 확인
7. **다국어** — 문자열은 하드코딩하지 말고 키로 출력, 문장 조립 금지 → [i18n.md §4~5](./i18n.md)
